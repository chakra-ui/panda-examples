# Agent guide: the panda-app example

This app runs its own Panda and pulls the `pandacn` design system from npm through `designSystem`. Read [`README.md`](README.md) for how it works and [`PANDA.md`](PANDA.md) for the Panda API.

## Where imports come from

This is the one that trips people up:

- `css`, `cx`, patterns, and jsx come from your local `../styled-system/*`, generated by this app's Panda.
- Components (`Button`, `Card`, `Badge`, and so on) come from `pandacn`.

Never import `css` or `cx` from `pandacn`. Never import components from `styled-system`.

## Using the design system

The design system's tokens and recipes are already in your build through `designSystem: 'pandacn'`. Use them directly: `css({ bg: 'primary' })`, recipe props, all of it. Don't redeclare a token the system already defines.

Extend, don't fork. App-only tokens go under `theme.extend` in `panda.config.ts` — this app adds `colors.brand` that way. See `components/showcase-extend.tsx`.

Keep `@pandacss/preset-base` and `@pandacss/preset-panda` as devDependencies. The design system's recipes are built on Panda's default scales, so the presets have to resolve. Don't list them in `presets`; `designSystem` handles that.

## Building

`predev` and `prebuild` run `panda build`. If styles are missing or stale, run `panda build`. Don't edit `styled-system/` — it's generated.
